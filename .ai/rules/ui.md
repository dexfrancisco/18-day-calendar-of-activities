# UI/UX Rules

- Inspect and reuse the actual project's design system and component library before building new components.
- For substantial frontend work, consult installed `design-taste-frontend` and `ui-ux-pro-max` skills when available, plus relevant design-system, typography/color, layout, responsive-design, accessibility, dashboard, forms, data-dense UI, audit UI, and testing skills.
- Define a product-specific visual direction and information hierarchy before implementation.
- Avoid generic AI-looking design defaults and decorative elements without a product purpose.
- Use coherent design tokens, meaningful content, useful density, responsive layouts, keyboard-accessible interactions, and clear loading/empty/error states.
- Do not invent metrics or business records to make a UI look populated.
- Update `.ai/memory/ui-ux.md` when durable design decisions change.
- Verify in-browser when available; report checks not performed honestly.
